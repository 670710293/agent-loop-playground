# Agent Loop Playground

เว็บสาธิตแนวคิดการแบ่งงานให้ AI Agent แต่ละตัวรับผิดชอบคนละหน้าที่ เพื่อจัดการงานค้นคว้าและการเรียนรู้ โดยมีหน้าเว็บหลัก 2 หน้า และออกแบบให้เผยแพร่ผ่าน GitHub Pages ได้โดยตรง

## Live-Demo

สามารถเผยแพร่โปรเจกต์นี้ด้วย GitHub Pages ได้ที่  
**Settings → Pages → Deploy from a branch → เลือก `main` → `/ (root)`**

## เนื้อหาข้างในเว็บไซต์

- `index.html` — หน้า Learning Assistant สำหรับส่งคำถาม ดูขั้นตอนการทำงานของ Agent รับชีทสรุป และอ่านส่วนเปรียบเทียบ Single AI กับ Multi-Agent
- `models.html` — หน้า Model Explorer สำหรับสำรวจโมเดลเฉพาะทาง 6 หมวด เช่น Coding, Image Generation, Audio, Search & Research, Embeddings และ Vision/Document
- `agents.html` — หน้าเปลี่ยนเส้นทางเพื่อรองรับลิงก์เก่าที่เคยชี้มาหน้า Agents

## ระบบสาธิตทำงานอย่างไร?

1. **Planner** อ่านคำถามและแยกหัวข้อ; ระบบตรวจภาษาภายในเพื่อสร้างคำค้นสองภาษาโดยอัตโนมัติ
2. **Researcher** สร้างคำค้นไทยและอังกฤษ ค้น Wikipedia และ DuckDuckGo Instant Answer ทั้งสองภาษา พร้อมแหล่งเฉพาะทางตามหมวด เช่น GitHub, Crossref, OpenAlex, PubMed, GDELT และ World Bank
3. **Analyst** เลือกเฉพาะแหล่งที่มีเนื้อหาจริงและให้คะแนนความเกี่ยวข้องเบื้องต้น
4. **Writer** รวมประเด็น ตัดข้อความซ้ำ แปลข้อความอังกฤษเป็นไทย และจัดเป็นชีทสรุป Markdown
5. **Reviewer** ตรวจโครงสร้าง ความซ้ำ และ URL อ้างอิงก่อนส่ง

### ข้อสำคัญเกี่ยวกับความสามารถจริง

Agent ทั้ง 5 บทบาทในเวอร์ชันนี้เป็นขั้นตอนการทำงานที่เขียนด้วย JavaScript แบบ Rule-based ไม่ใช่ LLM 5 ตัวที่สนทนาหรือทำงานอิสระร่วมกัน

- แหล่งข้อมูลภายนอกที่รองรับ ได้แก่ Wikipedia ไทย/อังกฤษ, DuckDuckGo Instant Answer ไทย/อังกฤษ และ API เฉพาะทาง ได้แก่ GitHub, Crossref, OpenAlex, PubMed, GDELT และ World Bank
- การคัดเลือกประเด็น การเรียบเรียง และ Reviewer ทำงานด้วย Logic ใน Browser; การแปลภาษาอังกฤษเป็นไทยเรียกบริการ MyMemory ภายนอก
- Reviewer ตรวจโครงสร้างเบื้องต้น ไม่ได้ตรวจสอบความจริงของเนื้อหาเชิงความหมาย
- ส่วนเปรียบเทียบ Single AI vs Multi-Agent เป็นเนื้อหาเพื่อการเรียนรู้ ไม่ใช่ผลการทดลอง Benchmark

## วิธีเปิดใช้งานบนเครื่องตัวเอง

## ข้อจำกัดของเวอร์ชันนี้

- DuckDuckGo Instant Answer ไม่ใช่ Web Search แบบเต็มรูปแบบ; ยังไม่มี Search API ที่ค้นเว็บได้ครอบคลุมทั้งหมด
- การแปลผ่าน MyMemory เป็นบริการภายนอก อาจติด rate limit, CORS หรือแปลศัพท์เฉพาะผิดได้; ควรตรวจคำแปลสำคัญ
- การค้นหาและดึงข้อมูลขึ้นกับการให้บริการของ API และเครือข่าย
- การวิเคราะห์ข้อความและ Reviewer ใช้กฎ/heuristic ไม่เทียบเท่าการสรุปหรือ fact-check โดย LLM
- Model Explorer เป็นรายการตัวอย่างโมเดลเฉพาะทางที่คัดเลือกไว้ ไม่ใช่การจัดอันดับแบบเรียลไทม์
- ชื่อรุ่น ความสามารถ ราคา และ License ของโมเดลอาจเปลี่ยนแปลง ควรตรวจเอกสารทางการก่อนใช้งานจริง
- ยังไม่มี Backend, ระบบสมาชิก, Cloud Sync, ประวัติการสนทนา หรือ LLM Provider จริง
- Frontend ไม่ต้องใช้ API Key หรือ Secret

## แนวทางพัฒนาต่อในอนาคต

สามารถเพิ่มแหล่งค้นคว้าอื่น เพิ่ม LLM Provider ผ่าน Backend เพิ่มระบบบันทึกประวัติการสนทนา และพัฒนา Reviewer ให้ตรวจสอบข้อกล่าวอ้างกับแหล่งข้อมูลได้
- ลองพิสูจน์แล้ว และลองปรับให้เพิ่มแหล่งข้อมูลแล้ว ตัว Multi-Agent จะทำงานไม่ดีเท่าตัวของ Single AI ด้วยความที่ตัว Multi-Agent จะไม่มีตัว Backend + LLM จึงทำให้จำกัดเท่านี้ และแหล่งเสิร์ชข้อมูลที่ไม่เทียบเท่าตัว Ai ต่างๆ

หากต้องการพิสูจน์ว่า Single AI หรือ Multi-Agent เหมาะกับงานใดมากกว่า ควรออกแบบชุดโจทย์เดียวกัน เกณฑ์ประเมินที่โปร่งใส และวัดคุณภาพ เวลา รวมถึงต้นทุนจริงก่อนสรุปผล
- ปกติตัวคนใช้ จะใช้ตัวของ Single AI มากกว่า แต่เนื่องจากสงสัยและอยากแชร์ให้ทุกคนได้ลองฝั่งนี้ จึงลองสร้างตัวของ multi-agent ขึ้นมาเพื่อที่จะได้ติดตามและแก้ไขผลได้
  
อ่านรายละเอียดเพิ่มเติมได้จาก `PROJECT_PLAN.md` และไฟล์ `docs/PHASE-*.md`

## v8.3 — ค้นสองภาษาและสรุปภาษาไทย

ระบบไม่มีตัวเลือกภาษาแล้ว โดยพยายามค้นทั้งภาษาไทยและอังกฤษอัตโนมัติ ใช้บริการแปลคำค้นเมื่อจำเป็น และแปลประเด็นภาษาอังกฤษเป็นไทยก่อนเรียบเรียงผลลัพธ์ ตัดส่วน Keywords ออกจากชีท และเปลี่ยน Self-review เป็นคำถามสะท้อนความเข้าใจที่อิงคำถามต้นฉบับ เพิ่ม timeout และข้อความแจ้งข้อผิดพลาดเพื่อไม่ให้หน้าจอค้างเงียบเมื่อ API ไม่ตอบสนอง

ข้อจำกัด: DuckDuckGo Instant Answer ไม่ใช่ full web search; การแปลพึ่งพา MyMemory; API อาจถูกจำกัด; Reviewer ตรวจโครงสร้าง ไม่ได้ตรวจความหมายหรือข้อเท็จจริงแบบ LLM. รายละเอียดอยู่ใน `PROJECT_STATUS.md`.
